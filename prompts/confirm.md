# 确认草稿

- **版本**：v0.3
- **用途**：根据原始逐字稿与画面词表，列出需要维护者确认的条目。不是评课，不打分。

只返回一个 JSON 对象。不要改逐字稿原文。维护者会逐条被问到 `terms` 里画面为空的条目，因此**宁可少列，不要多列**。

## 专名

对照 `transcript` 与整份 `screen` 词表。画面词表覆盖整段课，**不要求与稿上同一时刻**。

1. **稿 vs 画面**：稿上的专名像听写错误，且画面上出现过更可能的写法。列入，并填 `screen` 与 `snapshot`。同一 `heard` 只列一次（用最早出现的时刻）。
2. **画面没有**：只列「专名被听成另一个词或无意义碎片」，例如英文工具名被听成另一个英文词。`screen` 与 `snapshot` 留空。

第 2 条**最多 5 条**，只保留最像专名乱码的。不要列：

- 已经通顺、能认的中文或英文（如课程名、算法名、产品名本身）
- 成语、口头禅、完整口语短句、单个常用词
- 看起来像真实缩写的短字母（两三个字母）
- 没有十足把握的条目

不要根据常识擅自写成「正确专名」——你只负责把可疑听写列出来。同一句话里连续两段听写可以合成一条 `heard`。

每条包含：`clock`、`heard`、`screen`（没有则空字符串）、`snapshot`（没有则空字符串）。

## 开场三项（仅 `stage_first`）

若稿上没有自我介绍、班级约定或今日目标，把对应键放入 `opening_needed`：`self_intro` / `class_norms` / `today_goal`。不要猜测「下一段视频才有」。其他课型让 `opening_needed` 为空数组。

## 输出

```json
{
  "terms": [
    {
      "clock": "00:10:10",
      "heard": "CRT决策数",
      "screen": "CART决策树",
      "snapshot": "snapshot/00-10-10.jpg"
    },
    {
      "clock": "00:21:32",
      "heard": "DeFi打遍",
      "screen": "",
      "snapshot": ""
    }
  ],
  "opening_needed": ["self_intro", "class_norms", "today_goal"]
}
```
