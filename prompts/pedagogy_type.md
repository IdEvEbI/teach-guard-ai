# 课型识别

- **版本**：v0.1
- **用途**：给单段授课视频标注一个主类型，供后续步骤回链对应专文。不是评分，不是改稿。

根据「文件名 + 开篇约 2 分钟标点稿 + 全段时长」判断主类型。只返回一个 JSON 对象。

## 枚举（必须恰好选一个）

| 值            | 含义           | 回链专文 | 常见合格线（摘要）                                          |
| ------------- | -------------- | -------- | ----------------------------------------------------------- |
| `stage_first` | 阶段第一课开场 | 004      | 开场四部分合计约 30～40 分钟；本段常是「学什么」15～20 分钟 |
| `intro`       | 简介类         | 005      | 约 10～15 分钟；某一模块前的用语铺垫，勿讲成百科            |
| `practice`    | 实操类         | 006      | 演示加随堂不超过一节课；禁止只念讲稿                        |
| `syntax`      | 代码语法类     | 007      | 一知识点一视频约 10～20 分钟                                |
| `case`        | 案例类         | 008      | 综合应用当天知识点完成可运行小业务                          |
| `principle`   | 原理类         | 009      | 一交付点一视频；单段不超过 30 分钟                          |
| `project`     | 项目类         | 010      | 接近企业实践的完整交付；勿讲成语法课                        |
| `other`       | 无法判定       | —        | 依据不足时选用，不要假装高置信                              |

## 阶段第一课与简介类（最容易判错）

`stage_first` 不是简介类。阶段第一课开场依次是：学什么、自我介绍、班级约定、今日目标。其中「学什么」是**本阶段地图**：阶段在培养链中的位置、阶段末能做出什么、各天板块一览。只作概览，不把各天展开成正课。

简介类是**某一知识模块开始前**的短铺垫（例如某技术发展史、某术语简介），用来建立后续听课用语，约 10～15 分钟。

因此：

- 文件名即使含「大纲」「介绍」「了解」，只要口头主线是「这几天 / 本阶段学什么、了解即可」，选 `stage_first`，不要选 `intro`。
- 不要因为时长超过 15 分钟就把阶段地图改判成原理课。
- 本段若只录了开场中的「学什么」，仍选 `stage_first`，并在 `delivery` 写明只覆盖了哪一部分。

每日反馈、作业讲评、全天总结等固定环节不是六课型，选 `other`，并在 `reasons` 写明。

## 主交付

用一句话写 `delivery`：学员听完这段应带走什么。不要写成老师个人评价。

## 输出

只返回 JSON，不要 Markdown 围栏，不要解释：

```json
{
  "lesson_type": "stage_first",
  "confidence": "high",
  "delivery": "建立本阶段四天地图，了解即可，不深挖算法。",
  "ruler": "004",
  "reasons": ["开篇说明本阶段课程设计一共四天", "文件名是大纲介绍"],
  "not_type": "intro",
  "not_reason": "这是阶段地图，不是某一模块前的用语铺垫。"
}
```

`confidence` 只能是 `high`、`medium` 或 `low`。依据不足时 `lesson_type` 必须是 `other`。
