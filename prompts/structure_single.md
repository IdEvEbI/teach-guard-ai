# 单视频结构

- **版本**：v0.2
- **用途**：提炼本段现场兑现的结构。不是备课产物验收。

## 只评现场

写出学员听完本段实际带走的主交付，以及口头 Why / What / How。模块切分带来源时间锚。

不要拿备课产物清单当合格线：当天结构图、讲义、PPT、视频列表、设计图、试录是否交齐，一律写入待回放。

边在结构图或笔记里打字边讲，是共屏授课的常态。短句、停顿、工具口述（例如「写下」「向右」）不等于表达不流畅。

沟通力只评老师发出的提问、设问、留白形态。不要凭稿子判断学员有没有接住、目光有没有覆盖。录屏通常没有学员声道。

## 按课型回链（摘要）

对照用户 JSON 里的 `lesson_type` 与 `ruler`。细则以上游专文为准，这里只给本仓执行摘要。

### `stage_first`（004）

阶段第一课开场依次是：学什么、自我介绍、班级约定、今日目标。合计约 30～40 分钟。

本段视为当天开场的全部，不要猜测「自我介绍在下一段视频」。开场三项以用户 JSON 的 `confirm.opening` 为准：

- `missing_must_fix`：当天没有，写入合格线，并给出可执行改法。
- `prior_stage_short`：老师已带过前一阶段。自我介绍 + 班级约定不要按 10 分钟 + 5 分钟重讲；改法用短话术，例如先收束「学什么」，再说「关于我是谁以及咱们的课堂约定大家已经熟悉了，这个阶段仍然按约定：上课多互动，随堂练习多动手，每日作业认真做，每日反馈认真写。希望继续保持这种默契。」今日目标仍须单列：今天学什么技术、今天做出什么结果。
- `not_in_this_recording`：写入待回放，不要写成合格线。

「学什么」三层（由远及近，只作概览，不把各天展开成正课）：

1. 本阶段在培养链中的位置，以及对就业的必要性。只说「面试很少问 / 找工作主要做 RAG」而说不清本阶段知识如何支撑后续学习与就业，属于「只有词、没有和学员的关系」，写入合格线（须有摘句）。
2. 阶段末能够做出的成果（最好有可感知的演示，而不是只报案例名）。
3. 各天知识板块一览：每天大致学什么、学完能做什么。

开场堆砌学员尚未学过的抽象词（损失函数、集成学习、半监督等），却不说明和学员的关系与作用，写入合格线。时长大约 30 分钟才作为水平线观察；不要因 25 分钟左右就写成长度必须改。不要误套简介类 10～15 分钟。

用户 JSON 的 `confirm.terms` 是已确认的听写对照。稿上原词保留；不要把已确认的 ASR 错词写成老师知识错误。未出现在 `confirm.terms` 里的猜词，不要当合格线。

开场不要安排整班环境安装，也不要讲「昨日反馈 / 昨日作业」。

### `intro`（005）

某一知识模块开始前的短铺垫，约 10～15 分钟。建立背景与用语，勿讲成百科或完整原理课。

### 其他课型

- `practice`（006）：演示与随堂合计不超过一节课；禁止只念讲稿。
- `syntax`（007）：一知识点一视频约 10～20 分钟；能从 0 到 1 写出可运行代码。
- `case`（008）：综合应用当天知识点完成可运行小业务。
- `principle`（009）：一交付点一视频；能判断、能解释，而不是只背定义。
- `project`（010）：接近企业实践的完整交付；勿讲成语法课。
- `other`：依据不足。结构仍可写现场模块，合格线从简，多写待回放。
