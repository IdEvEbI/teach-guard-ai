# 单视频结构

- **版本**：v0.6
- **用途**：提炼本段现场兑现的结构。不是备课产物验收。

## 只评现场

写出学员听完本段实际带走的主交付，以及口头 Why / What / How。模块切分带来源时间锚。用完整句子，不要电报体。

不要拿备课产物清单当合格线：当天结构图、讲义、PPT、视频列表、设计图、试录是否交齐，不要写入报告。

边在结构图或笔记里打字边讲，是共屏授课的常态。短句、停顿、工具口述（例如「写下」「向右」）不等于表达不流畅，也不等于提问后的留白。

沟通力只评老师发出的提问、设问、以及提问之后有没有停顿。不要凭稿子判断学员有没有回答、目光有没有覆盖。

合格线按三力分开写，每条带 `force`：

- `design`：现场有没有按该课型该有的结构教。
- `communication`：提问、设问、空问是否用得合适。设问允许自问自答。
- `expression`：口头有没有引入、展开、收束；术语是否先通俗后专名。不要评吐字、音量、目光。

## 按课型回链（摘要）

对照用户 JSON 里的 `lesson_type` 与 `ruler`。细则以上游专文为准，这里只给本仓执行摘要。

### `stage_first`（004）

阶段第一课开场依次是：学什么、自我介绍、班级约定、今日目标。合计约 30～40 分钟。

本段视为当天开场的全部，不要猜测「自我介绍在下一段视频」。覆盖行必须写成老师能读懂的中文，不要写出内部代号。开场三项以确认结果为准，不得把已确认的选项写成「未包含」。

必须填写 `structure.learn_what` 三层，`layer` 只能是 `chain` / `outcome` / `days`，`status` 只能是 `covered` / `partial` / `missing`，并写 `note`。有摘句时补 `clock` 与 `quote`。

1. `chain`：本阶段在培养链中的位置，以及对就业的必要性。必须落到稿上的具体说法（例如「来时路」「面试很少问」「找工作主要做 RAG」）。只说抽象重要性而说不清本阶段知识如何支撑后续学习与就业，写入合格线（`force` 为 `design`）。
2. `outcome`：阶段末能够做出的成果。只报案例名、没有让学员看见结果，写入合格线（`force` 为 `design`）。
3. `days`：各天知识板块一览：每天大致学什么、学完能做什么。只作概览，不把各天展开成正课。

- 今日目标当天没有：写入合格线（`force` 为 `design`）。改法收到**今天**学什么、今天解决什么问题，不要把四天大纲复述成今日目标。
- 自我介绍与班级约定已带过前一阶段：不要按 10 分钟 + 5 分钟重讲。若稿上没有短收束，写入合格线（`force` 为 `design`），并给出可直接说的短话术。例如：「关于我是谁以及咱们的课堂约定，大家已经熟悉了。这个阶段仍然按约定：上课多互动，随堂练习多动手，每日作业认真做，每日反馈认真写。」
- 开场堆砌学员尚未学过的抽象词（损失函数、集成学习、半监督等），却不说明和学员的关系：写入合格线（`force` 为 `expression` 或 `design`，按主要缺口选一个）。
- 时长大约 30 分钟才作为水平线观察；不要因 25 分钟左右就写成长度必须改。

开场不要安排整班环境安装，也不要讲「昨日反馈 / 昨日作业」。

用户 JSON 的 `transcript` 已是确认逐字稿。摘句用这份稿。不要把已替换后的正确专名写成老师知识错误。

### `intro`（005）

某一知识模块开始前的短铺垫，约 10～15 分钟。建立背景与用语，勿讲成百科或完整原理课。

### 其他课型

- `practice`（006）：演示与随堂合计不超过一节课；禁止只念讲稿。
- `syntax`（007）：一知识点一视频约 10～20 分钟；能从 0 到 1 写出可运行代码。
- `case`（008）：综合应用当天知识点完成可运行小业务。
- `principle`（009）：一交付点一视频；能判断、能解释，而不是只背定义。
- `project`（010）：接近企业实践的完整交付；勿讲成语法课。
- `other`：依据不足。结构仍可写现场模块，合格线从简。
