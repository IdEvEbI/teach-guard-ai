## 1. 原则

- **业务口径以上游为准**。本仓提示词是执行层，不是立法层。
- 引用时写明上游相对路径与文首版本号，便于回溯。
- 冲突时以上游最新正文为准，并回改本仓摘要与日后的 `prompts/`。
- **不要**把课研打分表当成日常检查的通过标准。分数评定在产品上后置。
- 本仓为 public 仓库：上游文中若有维护者真名、机构名或对外品牌名，**不要抄进**本仓文档与提交说明。

薄标准第 5 节对言行只做分类索引；条文冲突时以 A07 为准。

做课齐备性（讲义、结构图、练习是否备齐）通常无法从单段转写核验，应写入「待回放确认」，不得仅凭稿子写成合格线必改。

沟通力（上游课堂沟通与表达）：本阶段只评老师发出的提问、设问、留白等交互形态；不凭稿子判断学员是否接住、目光是否覆盖。边敲边讲造成的短句与停顿，不作为表达不流畅的依据。

课程设计：单视频精查提炼**现场兑现的结构**（主交付、模块、口头 Why / What / How）。上游「一天备课与自检」的产物清单（结构图、讲义、PPT、视频列表、设计图、试录）不是本阶段 `inspect` 的通过标准。

## 3. 提示词落盘（实现阶段）

实现单视频核心时，建议按文件拆分，避免把全部口径塞进一条提示词：

```text
prompts/
  system_tone.md       # 三不三要、合格线 / 水平线、文风
  punctuate.md         # 分段标点、不改词
  pedagogy_type.md     # 六课型识别
  knowledge_cases.md   # 概念与示例
  structure_single.md  # 单视频结构
  coach_feedback.md    # 提升建议（不打分）
  conduct_scan.md      # 批量言行扫描（对齐 A07）
```

变更评价维度时：先确认上游已有表述 → 更新本仓 PRD 或本文 → 再改 `prompts/` → 用同一课例对比报告差异。
